# 通用工程规范

适用于采用本工具包的项目。前端和后端的框架约定由各自的技术栈规范补充。用户当次明确指令优先；已有项目保留仍有效的约定，并记录与本规范的差异。

## 开发边界

- 修改前阅读项目入口与相关规范，确认本次范围和适用检查。围绕真实职责组织模块；由最近的使用方维护实现，出现稳定的共同职责后再提取共享能力。
- 在 HTTP、文件、事件和第三方响应等信任边界验证数据。类型声明不能代替运行时校验。保留缺失、空值和无效值之间有业务含义的差别；异常不能静默转成成功或空结果。
- 单一来源维护公开契约。变更字段、状态、错误码或行为时，同步核对所有调用方、测试和文档；破坏性变更说明兼容期或迁移路径。

## 文档与注释

- 新增或修改的文档和注释使用中文，保留技术标识符、命令、协议和官方名称。生成文件、第三方代码、许可证和工具指令保留原格式。
- 注释必须遵循[中文代码注释规范](comments.md)，并同时读取所选技术栈中的文件头、公开声明和各类文件最低说明。共用阶段阈值、有效行数、TODO 标记及例外在该文件维护。

## 文件规模与职责预警

| 文件类型 | 推荐范围 | 预警范围 | 处理方式 |
| --- | ---: | ---: | --- |
| 前端页面入口 | ≤150 行 | 151～250 行 | 提取业务 Hook 或独立交互。 |
| 前端页面私有组件 | ≤200 行 | 201～350 行 | 按独立交互拆分。 |
| 前端公共组件、Hook、Store、工具 | ≤300 行 | 301～500 行 | 保持公开接口，按职责拆内部实现。 |
| Controller、Router、Module | ≤200 行 | 201～350 行 | 按稳定资源、用例或装配职责拆分。 |
| Service、Application 用例 | ≤250 行 | 251～400 行 | 拆查询、命令或独立能力。 |
| Domain | ≤300 行 | 301～500 行 | 按聚合规则或状态机拆分。 |
| Repository、文件 Store、外部 Adapter | ≤350 行 | 351～600 行 | 按聚合或外部能力拆分。 |
| 测试文件 | ≤500 行 | 501～800 行 | 按被保护的行为场景拆分。 |

文件行数是职责预警，与函数有效代码行的统计不同。超过预警上限时先整理职责；确需保留应说明原因，不继续叠加新职责。Schema、声明式配置、生成契约和 Migration 单独判断，不机械拆成碎片。

## 前后端共用的服务边界

- HTTP 入口负责协议转换，应用用例负责编排与授权，领域代码表达规则和不变量，存储及第三方调用由适配层处理。依赖按实际需要装配，不为简单功能预建空层。
- 新接口约定 HTTP 状态、稳定错误码 `code`、可展示的 `message` 和请求 ID 的传递方式。身份失效、无权或资源不可见、输入无效、业务冲突及内部故障应可区分。已有接口保持字段命名，由前端 Client 归一化；公开错误不包含堆栈、内部路径或秘密。
- 身份来自服务端验证的会话或令牌。对采用工作区或租户的项目，客户端传入的归属和资源 ID 都须校验；查询、更新、删除和任务读取都要限定授权范围。
- 多人在线且有关系型持久化需求的项目默认 PostgreSQL；纯本机单进程工具可以使用文件存储。数据库用事务和约束保护一致性，结构变化走版本化迁移并验证旧数据。文件写入说明并发范围、原子替换与损坏恢复；进程内互斥不能用于多个实例共享写入。
- 长时间工作移到独立任务执行，异步受理返回任务标识和可查询状态。业务写入后若必须可靠发出事件，可使用同事务记录事件的方式；远端调用不在长期持锁的事务内。任务明确版本、去重、重试上限与失败恢复，远端写入结果不明时先核对。
- 配置由启动边界集中读取与校验，环境配置和秘密与共享文件分离。请求和任务的日志保留排查所需的标识和状态，避免输出凭证、令牌及敏感正文。
- 时间采用带明确时区的 UTC 表示，公开时间优先 ISO 8601；公开字段注明大小、时间和摘要的单位或格式。稳定有限状态使用明确的类型表达。
- 数据损坏、解析失败或权限错误不能降级为空数据并覆盖原文件。唯一性在存储写入边界保护；失败整体回滚，不在未知状态继续复用事务。列表分页保持稳定排序，原生 SQL 参数化，批量操作明确上限与失败策略，避免 N+1 查询。
- 同一资源的并发更新采用版本或条件检查；旧任务晚到不能激活过期结果。工作区限制同时进入查询和写入条件，权限变化后重新校验；缓存键含作用域与资源版本，能够精确失效。
- 外部适配统一超时、有限重试、脱敏与错误分类。消息按至少一次投递考虑重复及乱序，任务恢复可信上下文并复核授权；执行事实、外部受理和最终完成分别记录，取消本地等待不等于撤回远端操作。
- 跨进程调用传播追踪上下文；采用 W3C 追踪时传递 `traceparent`。审计与运行日志分开，记录主体、动作、目标、结果和时间；指标标签保持有界，不以用户或请求 ID 作标签。连接池、任务并发与流式连接设置上限，性能优化以指标或测试为依据。

## 验证、配置与提交

- 将项目启用的规范、采用的工具包版本、技术栈、适用检查及项目差异记录在仓库内。共享规则使用仓库相对引用；本机路径、凭证和私有环境配置不进 Git。
- 新增或更新依赖时同步锁文件。已有项目沿用自身版本策略、格式化和检查配置；新的检查先实现并验证，再列为必跑项。
- 按改动运行项目实际定义的格式、静态检查、类型、测试和构建等适用检查。优先保护用户可见行为、失败恢复和跨层契约。界面改动按影响走真实页面；迁移和权限变更覆盖代表性旧数据与越权拒绝。区分通过、失败、未运行及待实际环境验收。
- 跨端契约或流程变更须同时阅读前后端规范。测试采用合成、可清理的数据和隔离存储；时间、UUID、网络及任务调度可控。工作区资源至少覆盖同空间允许、跨空间拒绝、缺失可信上下文拒绝；错误断言稳定码，不绑定完整展示文案。真实外部写操作须有具体授权，本地替身不能证明远端验收通过。
- 任务可独立验收并通过必要检查后，默认只暂存与提交本次改动，保留已有修改和部分暂存边界。提交标题采用 `<type>: <中文摘要>`，正文按需写中文修改列表。无变更不创建空提交，检查失败不绕过，按明确指令或项目启用的策略推送。
