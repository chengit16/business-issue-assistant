# NestJS 与 Fastify 后端规范

适用于 TypeScript 管理后台、业务 API、工作台及第三方接口集成。新建常规业务服务默认选用此套规范，并遵循[通用工程规范](../common/engineering.md)。已有项目保留已验证的接口和部署约定。

## 技术与模块

- 使用 Node.js、TypeScript、NestJS 和 Fastify adapter，由 pnpm 管理依赖。启用 `strict` 和 `noUncheckedIndexedAccess`，使用 `import type` 标注类型导入。公开入口明确输入和返回类型；外部输入从 `unknown` 开始校验。
- 默认从一个 API 服务开始，按业务域组织 Module。Controller 负责 HTTP 参数、响应和错误映射；Service 负责用例编排；领域层负责业务规则和状态转换；存储与外部 SDK 实现明确的端口，由 Module 装配。
- 当多个应用确需共享时，再将领域或公开契约提取到独立包，例如 `packages/domain` 和 `packages/contracts`。领域代码不依赖 NestJS、前端或第三方 SDK；前端不直接使用存储对象、内部 DTO 或 SDK 类型。
- 类、接口与类型使用 `PascalCase`，函数和变量使用 `camelCase`。NestJS 职责文件使用 `*.module.ts`、`*.controller.ts`、`*.service.ts`。保持既有公开字段命名。

## 公开接口

- 在入口校验参数、请求体与第三方响应，按需拒绝安全敏感请求中的未知字段。DTO 只描述传输数据，Controller 负责把数据转换为用例输入。
- TypeScript 工作区可维护共享公开契约和运行时守卫；也可从 OpenAPI 生成客户端契约。以项目选择的一处来源为准。响应只返回公开字段，敏感信息或执行器的本机路径不能穿透到接口。
- 错误在 HTTP 边界映射为公开状态和稳定业务语义。例如资源更新遇到版本冲突时，返回项目约定的冲突状态和错误码，调用方可保留草稿并重新读取当前版本。

## 存储与任务

- 在线业务需要关系型存储时默认 PostgreSQL。Node 侧数据库客户端、ORM 和迁移工具由项目确定；迁移、事务和恢复遵循通用规范。本机工具使用文件存储时，明确单进程限制及并发写入保护。
- 长时间执行或需要独立凭证的操作交给 Worker 或可信执行器。API 负责受理、状态和权限，Worker 从可信输入核对任务与目标，外部 SDK 及重试策略留在适配层；简单项目不预装队列。
- 认证使用项目选择的会话或令牌。本机专用且未认证的 API 仅在回环地址提供；跨设备部署按独立可信边界验证，不沿用本机的信任前提。

## 中文注释规范

必须同时执行[共用注释规则、阶段编号与长函数阈值](../common/comments.md)。

### 文件头、类与公开接口

所有新增手写 `.ts`、`.mjs` 文件，以及实际修改职责或行为的既有文件，必须提供中文 `@description` JSDoc 文件头，放在首个 `import` 前；有 shebang 时放在其后。生成文件、第三方代码和纯再导出入口除外。

普通文件说明维护主题；启动模块、Controller、Service、Domain、Store、Adapter、执行器与跨模块基础设施还说明职责、依赖方向、写入权，以及实际存在的授权、并发、事务或副作用边界。

```ts
/**
 * @description 本机项目文件存储
 *
 * 实现 ProjectStore，以同一进程内的串行写入和同目录替换保护数据。
 * 存储损坏时拒绝写入，不负责在线认证或多进程事务。
 */
```

新增或实际修改的公开顶层类、函数、接口、类型、跨模块常量与配置必须紧邻提供中文 JSDoc。Controller 公开端点与 Service 公开用例即使未直接导出，也须说明输入来源、返回事实与关键约束。装饰器声明的 JSDoc 放在装饰器前。

- 用例、Adapter 和执行器入口说明实际存在的前置条件、错误、副作用、幂等、事务与授权要求。签名中的自解释参数不机械重复写 `@param`。
- 端口在接口级说明方法集合的归属、读写、并发和失败约定；单个方法有额外约束时再说明。Adapter 类说明锁、文件、网络和事务差异，实现方法不重复抄写接口契约。
- 公开契约字段说明业务语义，自解释字段可由整体类型说明覆盖。不直观的默认、省略、状态、单位、时区、摘要格式、敏感级别和所有权字段必须单独注释。例如 `workspaceId` 说明由谁确定、是否构成授权，不能只写“工作区 ID”。
- 构造函数、框架固定生命周期及私有简单方法可由类级说明覆盖；额外非直观行为须单独说明，不能只将类名翻译成一句话。

### 各类文件最低说明

| 位置 | 必须说明 |
| --- | --- |
| 启动、Module | 运行模式、依赖装配、监听及可信上下文边界。 |
| Controller、错误过滤器 | 公开端点、协议映射、字段来源与安全错误投影。 |
| Service、用例 | 可信上下文、操作顺序、并发及副作用。 |
| Domain、端口 | 不变量、合法输入和状态、归属与可替换契约。 |
| 文件 Store、Repository | 写入权、锁或事务、唯一性、损坏处理与恢复限制。 |
| 公开契约 | 数据事实、字段默认和省略、单位、时区与安全边界。 |
| SDK Adapter | 可信调用方、能力差异、超时、重试及脱敏。 |
| 执行器、任务 | 授权核对、载荷版本、attempt、去重与人工核对。 |
| 脚本、迁移、测试 | 环境与清理、数据兼容与恢复，或被保护的业务行为。 |

## 验证与交付

- 采用[通用规模预警](../common/engineering.md#文件规模与职责预警)。运行项目可用的类型、测试、构建和格式检查，并检查中文注释的文件头、公开声明、字段与流程阶段。
- 优先用 Fastify 注入测试验证 HTTP 边界，用隔离合成数据测试授权、存储冲突、并发和历史兼容，用可控替身覆盖外部超时和结果不明；以行为而非私有实现细节断言。文件测试使用临时目录并清理。
- 本机回环 API 同时验证适用的 Host/Origin 限制；数据损坏不得覆盖原文件。跨端契约、存储或执行规则变化同步验证调用方迁移与恢复。
