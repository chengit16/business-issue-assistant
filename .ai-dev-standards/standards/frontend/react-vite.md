# React 前端规范

适用于采用本技术栈的新项目，配合[通用工程规范](../common/engineering.md)使用。已有项目接入时保留有效的请求层和现有配置，按实际改动补齐边界，不整体迁移。

## 固定技术选型

| 职责 | 首版选型与用法 |
| --- | --- |
| 构建与类型 | React、TypeScript、Vite、pnpm。开启 TypeScript `strict`，固定包管理器版本并维护锁文件。 |
| 组件 | Ant Design。表单、弹窗、表格优先复用组件；由应用入口的 `ConfigProvider` 统一语言和主题，通过公开 Token 和属性定制。 |
| 样式 | UnoCSS 用于常规布局、间距、响应式和状态样式；全局样式、焦点与复杂选择器可使用受控 CSS。集中维护语义设计变量，条件样式使用可静态识别的完整类名。 |
| 路由 | React Router。统一维护布局、路由、登录守卫与错误页；后端菜单驱动的路由按项目需要引入。客户端守卫不承担服务端授权。 |
| 客户端状态 | Zustand。用于跨页面共享的客户端状态，按领域分 Store，组件订阅所需片段。持久化采用字段白名单，只保存适合持久化的偏好。 |
| 常规 HTTP | Axios。由唯一 Client 入口封装；不在页面、组件、Hook 或 Store 里直接使用 Axios 或 `fetch` 发业务请求。 |

## 模块与状态归属

- `app/` 装配应用壳和 Provider，`routes/` 维护路由；`pages/{domain}/{feature}/` 放页面、业务 Hook 和私有组件。跨页面组件放 `components/`，公共组件不依赖具体路由。
- `api/client.ts` 维护传输边界，`api/services/` 按领域组织接口；`store/` 维护共享客户端状态，`styles/` 维护 Token 和全局样式。目录按真实职责建立。
- 服务端数据由页面业务 Hook 经 Service 管理；更新成功后重新读取或精确更新受影响的数据。首版不默认安装 TanStack Query；确需跨页面查询缓存、请求去重或后台刷新时再引入。查询键须覆盖工作区、资源、筛选和分页等影响结果的条件。
- 表单草稿、校验和弹窗状态优先留在拥有它们的组件或局部 Hook。请求失败保留输入，重新查询不覆盖未保存草稿。可分享、可刷新恢复的筛选和定位放 URL；不在 Store 重复保存 URL 或服务端数据。
- 切换账号或工作区时，取消或隔离旧请求与订阅，并清理受影响的状态和缓存。即使旧工作区的列表响应晚到，也不能覆盖当前页面。

## HTTP 请求

固定调用链：页面或业务 Hook → 领域 Service → Axios Client。

| 层 | 职责 |
| --- | --- |
| Client | 集中设置基址、请求凭证、超时、取消和错误归一化。按协议区分会话失效、取消、连接异常和服务端返回。请求中断只停止本地等待，不能当作服务端已撤销。 |
| Service | 维护路径、方法、参数、返回类型与数据转换。未知响应先验证，再返回可信类型。后端字段和协议差异收敛在这一层。 |
| 页面或业务 Hook | 管理加载、空数据、成功、失败及恢复动作；按接口支持区分无权和冲突。提交期间防重复触发。会话失效在应用入口统一处理，业务反馈由当前页面负责，避免重复提示。 |

- 基址、认证方式、响应结构和超时时间由接口契约及部署决定；不复制参考项目的固定包裹格式或会话刷新协议。需要刷新会话时集中处理并限制重放，默认不自动重试写请求；确有幂等保证时才配置有限重试。
- SSE、流式读取、下载或上传放在 `api/` 的专用模块，按协议选择合适的传输实现；例如流式响应可用 `fetch` 或 `EventSource`。专用模块仍遵守凭证范围、取消和错误边界。
- 浏览器存储、URL、日志和埋点不记录密钥、Cookie 或长期令牌；富文本和用户生成内容按不可信输入处理。

## 组件、样式与性能

- 组件及类型用 `PascalCase`，业务目录、Service 和普通函数用 `camelCase`，Hook 用 `useXxx`，Store Hook 用 `useXxxStore`；布尔值用 `is/has/can/should`，事件处理用 `handleXxx`，回调用 `onXxx`。保留既有契约字段，仅在 API 边界转换。
- TypeScript 开启未使用局部变量、参数和 switch 穿透检查；使用 `import type`，有限状态优先联合类型。禁止用 `any`、双重断言和非空断言掩盖缺失或未验证状态。
- 使用函数组件和 Hooks，公共组件优先具名导出，一个文件维护一个主要组件，列表用稳定业务 ID 作 key。渲染保持纯净，不在渲染时请求或写存储，不用 Effect 复制可推导状态；网络、订阅、计时器与存储同步明确触发和清理策略。
- Props 表达最小数据与回调约束。修改公共组件须保护 Props、ref、回调参数与时机、导出路径及稳定语义标识；破坏性变更列调用方和迁移方案。Hook 优先返回具名对象，稳定二元语义可用元组。
- `useMemo`、`useCallback`、`memo` 用于实际计算成本或稳定引用需求。按路由和大功能区评估懒加载，重型组件按需加载；长列表虚拟化、节流和缓存以实际规模与指标为依据。
- Ant Design 使用公开 Token、属性和语义化样式接口，避免依赖内部 DOM 或无范围覆盖 `.ant-*`。UnoCSS Safelist 只保留必要值；保留初始化副作用导入顺序，避免多层再导出隐藏依赖。
- 输入和按钮提供可读标签，键盘可完成主要流程，弹窗管理焦点，异步变化提供可访问提示，动画尊重 `prefers-reduced-motion`。应用壳和高风险功能区设置错误恢复边界，提供可执行的恢复入口。
- 使用 Cookie 会话时按服务端协议接入 HttpOnly 和 CSRF 防护；富文本、模型输出按允许列表处理。版本冲突保留草稿，不静默覆盖；异步任务以服务端末态为准，SSE 重连不重复触发业务写入。

### 文件头与公开接口

所有新增手写 `.ts`、`.tsx` 文件，以及实际修改职责或行为的既有文件，必须在首个 `import` 前提供中文 `@description` JSDoc 文件头；生成文件、第三方代码和纯再导出入口除外。普通文件说明维护主题；页面、业务 Hook、API、Store 和公共基础设施进一步说明职责、数据来源及权限或副作用边界。

```ts
/**
 * @description 项目列表的查询与创建交互
 *
 * 维护列表、表单草稿和提交状态；HTTP 协议交由 API Service 处理。
 * 创建失败保留用户输入，项目归属由服务端确定。
 */
```

新增或实际修改的导出组件、Props/Options 类型、Hook、Hook 返回对象类型、API Service、公共工具、Store、跨模块常量和配置，必须紧邻提供中文 JSDoc。说明用途及实际存在的关键参数、返回值、错误、前置条件和副作用，不机械重复名称。

Props 字段逐项说明；跨文件 Options、回调及复杂请求参数逐项说明默认值、省略及触发语义。`canEdit` 等字段须明确只控制界面。私有简单组件、类型和自解释赋值不逐项强制注释；字段可用单行 JSDoc。

```ts
/** 编辑面板的交互约定。 */
export interface EditorProps {
  /** 仅控制编辑入口展示，实际写入权限由服务端验证。 */
  canEdit: boolean;
  /** 服务端确认保存成功后触发；失败时保留草稿且不触发。 */
  onSaved: () => void;
}
```

### 各类文件最低说明

| 位置 | 必须说明 |
| --- | --- |
| 页面 | 文件职责、数据来源、主要状态与导出组件用途。 |
| Hook | Options、返回约定、异步竞争与清理；采用查询缓存时说明非默认启用、刷新和失效策略。 |
| API Client、Service | 公开契约、错误、取消、会话、工作区与安全边界。 |
| 公共组件 | 用途、全部 Props 字段和回调时机。 |
| Store | 状态所有权、持久化、重置和跨页面影响；公开 Action 的约束。 |
| SSE、权限配置 | 游标、重连、取消，或菜单、页面与接口授权的边界。 |
| 测试 | 被保护的业务行为；复杂场景的边界与数据约束。 |

复杂条件和不直观的响应式重排说明原因；普通 JSX 不添加无价值区域标题。Effect 解释触发与清理，缓存变更说明失效原因；流程阶段和函数拆分按共用阈值执行。

## 验证与交付

- 按[通用规模预警](../common/engineering.md#文件规模与职责预警)检查职责。运行已有格式、Lint、类型、测试和构建检查，检查新增文件、公开接口、字段及阶段注释。未建立的检查不得报告为已通过。
- 验证请求取消、旧响应隔离、失败恢复、冲突保留草稿及关键用户流程。界面改动按影响验证桌面、窄屏、键盘和焦点；路由改动验证刷新、深链和前进后退。测试优先通过角色、标签和可见行为定位，网络替身放在 Service 边界。
